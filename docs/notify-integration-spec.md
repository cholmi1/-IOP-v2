# 안압케어 IOP — 반납 알림 스케줄러 · 발송 채널 연동 명세

C&V Tech · CVT200 Companion / v1.0 / 작성 기준일 2026-08-13

프런트엔드 프로토타입(`anapcare-iop-app-v2.jsx`)에 구현된 알림 자동화를 실제 서비스로 옮기기 위한 서버 측 명세입니다. 화면 동작과 1:1로 대응하도록 작성했습니다.

---

## 1. 전체 구조

```
[Cron 스케줄러]  매일 09:00 (기관별 설정)
      │
      ▼
[대상 산출 Job]  대여 기기 중 D-3 / D-1 / D-0 / 연체 추출
      │
      ▼
[발송 큐]  단계별 채널 매핑 → 메시지 생성
      │
      ├─▶ [푸시 어댑터]  FCM(Android) / APNs(iOS)
      ├─▶ [SMS 어댑터]   문자 발송사 API
      └─▶ [콜 리스트]    담당자 화면에 노출 (자동 발송 아님)
      │
      ▼
[감사 로그]  발송 시각·환자·기기·단계·채널·결과·처리자 기록 (수정 불가)
      │
      ▼
[수신 중단 판정]  연체 > 유예일 → 해당 기기 측정 데이터 수집 차단
```

---

## 2. 알림 단계 판정 규칙

`dd = 반납예정일 − 기준일` (일 단위)

| dd | 단계 코드 | 기본 채널 | 데이터 수신 |
|---|---|---|---|
| 3 ~ 2 | `d3` | 푸시 | 정상 |
| 1 | `d1` | 푸시 + SMS | 정상 |
| 0 | `d0` | 푸시 + SMS | 정상 |
| −1 ~ −(유예−1) | `overdue` | 푸시 + SMS + 콜 | 정상 (잔여 유예일 안내) |
| ≤ −유예 | `blocked` | 푸시 + SMS + 콜 | **차단** |

- 유예일(`grace`)의 기본값은 3일이며 기관별로 0~14일 설정 가능합니다.
- `dd > 3`이면 대상에서 제외합니다.
- **개인 소유 기기는 판정 대상이 아닙니다.** 반납 개념이 없으므로 `owner = 기관`이고 `use = home`이며 `assignedTo`가 있는 기기만 조회합니다.

## 3. 배치 Job 사양

**실행 주기** — 기관별 설정 시각에 1일 1회. 다기관 운영 시 기관 타임존 기준으로 개별 실행합니다.

**멱등성** — 재실행이나 장애 복구 시 중복 발송을 막기 위해 `(device_serial, level, 발송일자)`를 유니크 키로 둡니다. 같은 키가 이미 성공 기록으로 존재하면 건너뜁니다. 단, `overdue` 단계에서 `resendDaily`가 켜져 있으면 날짜가 다르므로 매일 1회씩 정상 발송됩니다.

**야간 발송 제한** — `quiet`가 켜져 있으면 21:00~08:00 구간의 발송은 큐에 보관했다가 다음 허용 시각에 내보냅니다. 의료 목적 안내라도 심야 발송은 민원 소지가 큽니다.

**재시도** — 채널별로 최대 `retry`회(기본 2회), 지수 백오프(1분 → 5분)로 재시도합니다. 최종 실패는 로그에 `실패`로 남기고 담당자 화면에 노출합니다.

**부분 실패 처리** — 한 건에 여러 채널이 걸린 경우 채널별로 결과를 남기고, 전체 결과는 다음과 같이 집계합니다.

| 채널 결과 | 전체 결과 |
|---|---|
| 전부 성공 | 성공 |
| 일부만 성공 | 부분 실패 |
| 전부 실패 | 실패 |

## 4. 채널 어댑터

### 4.1 앱 푸시 (FCM / APNs)

- 기기 토큰은 환자 계정 단위가 아니라 **설치 기기 단위**로 보관하고, 로그아웃·앱 삭제 시 무효화합니다.
- `NotRegistered`, `InvalidRegistration` 응답을 받으면 토큰을 즉시 폐기하고 재시도하지 않습니다. 프로토타입 로그의 "푸시 토큰 만료" 케이스가 이에 해당합니다.
- 페이로드에는 개인 식별 정보를 넣지 않습니다. 본문은 "대여 기기 반납 예정일이 내일입니다" 수준으로 유지하고, 상세는 앱을 열어 확인하게 합니다.
- 알림 클릭 시 딥링크로 설정 화면의 반납 관리 영역을 엽니다.

### 4.2 SMS

- 국내 발송은 사전 등록된 발신번호가 필요하며, 광고성이 아닌 **정보성 문자**로 분류되도록 문안에 광고 문구를 넣지 않습니다.
- 수신 거부 번호는 발송사에서 차단되므로 실패 코드를 그대로 기록합니다.
- 해외 환자(미국·중국)는 국가번호와 발송사가 달라 별도 라우팅이 필요합니다. 개인 소유 기기 비중이 높은 국가는 SMS 발송 대상이 적습니다.

### 4.3 유선 안내

자동 발송이 아니라 **콜 리스트 생성**입니다. 담당자가 통화 후 결과를 직접 입력하면 로그에 `수동 / 처리자명`으로 남습니다.

## 5. 데이터 수신 중단 정책

연체가 유예일을 넘기면 해당 기기의 측정 데이터 업로드를 서버에서 거부합니다.

- 환자 앱은 **로컬 저장을 계속 유지**합니다. 데이터를 잃게 만들면 안 됩니다.
- 반납 처리 또는 기간 연장이 이뤄지면 차단을 즉시 해제하고, 앱이 보관 중이던 미전송 측정값을 **일괄 재전송**합니다.
- 차단 상태에서도 앱의 측정 기능 자체는 막지 않습니다. 안압 측정은 환자의 건강 관리 행위이므로 행정적 사유로 차단하지 않습니다.
- 차단 사실은 환자 앱 홈·측정 화면과 의료진 웹 기기 탭 양쪽에 표시합니다.

## 6. 감사 로그 스키마

```sql
CREATE TABLE notify_log (
  id              BIGSERIAL PRIMARY KEY,
  sent_at         TIMESTAMPTZ NOT NULL,
  org_id          BIGINT      NOT NULL,
  patient_id      BIGINT      NOT NULL,
  device_serial   VARCHAR(32) NOT NULL,
  level           VARCHAR(16) NOT NULL,   -- d3 | d1 | d0 | overdue | blocked
  channel         VARCHAR(16) NOT NULL,   -- push | sms | call
  mode            VARCHAR(8)  NOT NULL,   -- auto | manual
  actor           VARCHAR(64) NOT NULL,   -- 스케줄러 또는 직원 계정
  result          VARCHAR(16) NOT NULL,   -- success | partial | fail
  provider_msg_id VARCHAR(128),
  error_code      VARCHAR(64),
  detail          TEXT,
  UNIQUE (device_serial, level, mode, (sent_at::date), channel)
);
```

- **수정·삭제 금지.** 정정이 필요하면 반대 기록을 추가하는 방식으로 처리합니다.
- 보존 기간은 기관 정책에 따르되 3년 이상을 권장합니다.
- 조회 API는 기관 범위로 제한하고, 관리자만 CSV 내보내기를 허용합니다.

## 8. 개인정보 · 규제 고려사항

- 발송 문안과 푸시 페이로드에 진단명·측정값을 포함하지 않습니다. 잠금화면 노출 위험이 있습니다.
- 국가별 규정이 다릅니다. 국내는 개인정보보호법·의료법, 미국은 HIPAA, 중국은 PIPL(국경 간 이전 제한)이 적용되므로 발송 데이터는 지역별로 분리 보관합니다.
- 알림 수신 동의는 가입 시 받되, **반납 관련 통지는 대여 계약 이행을 위한 필수 고지**로 분류할 수 있는지 법무 검토가 필요합니다. 마케팅 수신 동의와 분리해 관리하세요.
- 본 알림은 기기 반납이라는 행정 사항을 다루며 진단·치료 판단을 포함하지 않으므로, SaMD 표시 경계를 넘지 않도록 문안에 의학적 권고를 넣지 않습니다.

## 9. 개발 우선순위 제안

1. 대상 산출 Job과 감사 로그 테이블 (발송 없이 로그만 쌓아 규칙 검증)
2. 푸시 어댑터 연동 및 D-3 / D-1 / D-0 발송
3. 수신 중단 판정과 재전송 로직
4. SMS 어댑터 및 연체 단계 발송
5. 콜 리스트, CSV 내보내기, 기관별 설정 화면

1~2단계만으로도 반납 연체의 상당 부분이 줄어들 것으로 보이며, SMS는 발신번호 등록과 발송사 계약에 시간이 걸리므로 병행 준비를 권합니다.
